# SIH Deck — Structural Reference (layout only, no borrowed content)

Captured from reference screenshots of other teams' SIH decks, for layout ideas when building/rebuilding the D-HITA slide deck. Structure only — none of the source teams' project content is reused here.

## Slide type 1 — Title / Problem / Idea / Solution overview
- Top strip: team name (top-left, in an oval/badge), full title centered, hackathon logo top-right.
- Below title, two columns:
  - Left: **Problem** — 2–3 bold-keyword sentences on the pain point.
  - Right: **Our Idea** — one short paragraph naming the solution and its core mechanism.
- Below that, two columns again:
  - Left: **Proposed Solution** — bullet list, key terms bolded, describing the architecture/approach (e.g. "3-layer" style breakdown).
  - Center: a product/device image or simple diagram.
  - Right: **Innovation / Uniqueness** — bullet list of differentiators, each bolded lead phrase + short explanation.

## Slide type 2 — Technical Approach
- Header bar with slide title.
- Left column: **Hardware & Software** — bullet list, each item bolded component name + one-line role (e.g. "Sensor X: does Y").
- Right column: **Flow Chart** — a boxed process diagram showing data/signal flow with labeled stages and decision branches.
- Bottom strip: repo/demo links (GitHub, YouTube) in a small box, plus a one-line progress status (e.g. "X% of the prototype is completed") called out in bold/red.

## Slide type 3 — Feasibility and Viability
- Four-quadrant grid, divided by a plus-shaped rule:
  - Top-left: **Feasibility** — bullets on technical practicality (what makes it buildable now).
  - Top-right: **Commercial feasibility** — market validation, technical readiness %, timeline, success-likelihood estimate.
  - Bottom-left: **Challenges** — bolded challenge name + one-line detail, short list.
  - Bottom-right: **Strategy** — bolded mitigation/approach name + one-line detail, matched roughly 1:1 against the challenges.

## Slide type 4 — Impact and Benefits
- Two columns:
  - Left: **Direct Impact on Target Users** — one bullet per user group, bolded group name + concrete benefit; followed by a **Strategic Impact** block (national/policy-level framing).
  - Right: **Economic & Strategic Benefits** — bolded metric/claim + one-line detail (cost reduction %, market size, partnership angle), with a small supporting bar chart placed below/beside it.

## Slide type 5 — Research and References
- Header: "Research and References".
- Numbered categories (e.g. Problem Validation, Technical Feasibility, Market & Application Validation), each with lettered sub-items:
  - Source name/publication (bold, italic) + one-line quoted or paraphrased finding + a clickable link line underneath.
- Categorizing references by *what they validate* (problem/technical/market) rather than listing them flat reads stronger than a plain numbered reference list.

## General visual patterns across all slides
- Consistent header bar (title centered or left, hackathon/theme logo top-right, team badge top-left).
- Two-column (or four-quadrant) layouts dominate — dense text is always paired with a visual (image, diagram, or chart) rather than run as a single full-width block.
- Bold lead phrases at the start of bullets, not full bolded sentences — keeps scanability high.
- One consistent accent color per deck, used for headers, dividers, and callout boxes.
- Slide numbers bottom-right/bottom-left; page footer accent bar at the very bottom in some decks.
